# Session resync + effort variants + loop guard

- Resync endpoint (`internal/server/server.go`): `GET /api/v1/sessions/{id}/state` returns one atomic payload (session + `running` + pending permission/question) for a (re)loaded client that missed SSE. `pendingForSession` re-renders modals missed while disconnected (else a blocked turn looks like stuck `working…` with no way to answer); `isRunning` recovers the spinner after a missed `turn.started`, transcript refetch covers a missed `turn.completed`. `PATCH sessions/{id}` updates agent/permission/model/title. `/continue` picks the latest previous session via SQLite `ORDER BY updated_at DESC` even without a store attached.
- TUI resync (`internal/tui/model.go`): `RequestResyncMsg` → `resyncCmd` → `ResyncMsg` → `applyResync`; `transcriptToLines` rebuilds the timeline. `Init` loads authoritative history on `-c`/`-s` attach; `/resume` picker drops the current session; `closeEmptyPickers` (a failed fetch must not leave an empty picker). Missed-started recovery: a progress row for an apparently-idle session (or a delta for one) rebuilds live state. Question modal is cyan, approval modal yellow; `toolGroup`/`toolLineStyle`/`statusStyle` color timeline groups.
- Effort variants (`internal/llm/llm.go`): `EffortVariants` (UI order), `NormalizeEffort` (`""`/`auto` → `""`), `ValidEffort`, `EffortLabel` (`""` renders `auto`), `EffortBudget` (Anthropic thinking budget in tokens). Provider-advertised ladder: `ModelMeta.SupportedEfforts` (empty = unknown → fall back to `EffortVariants`), `EffortsOrDefault` (prepends `auto`, intersects with `EffortVariants`), `ClampEffort` (over-request downgrades to highest supported step, under-request upgrades to lowest; `auto`/unknown pass through normalized), `EffortIndex` ordering (`auto` -1 … `max` 4). TUI `/variant` picker (`variantIndex`/`applyVariant`, `Effort` field, `variantPill`). Covered by `variant_matrix_test` + `effort_matrix_test` (TUI) and `effort_matrix_test` (server).
- Agent loop guard (`internal/agent/agent.go`): softCap 8 / hardCap 120 (was 40; `TestAgenticLoopAutoContinuesPastOldCap` proves 50 tool + final rounds with no budget summary). An identical tool round (same calls + args, via `roundCallKey`/`toolCallKey`) 3× in a row injects a nudge to change approach instead of re-calling — `task_output` polling is exempt (re-polling to completion is progress). Tool guidance + softCap checkpoints order CONTINUE-until-complete (no status-summary stop, no "say continue"); the 120-round exhaustion summary must name exactly what remains plus precise next tool calls. Child loop (`runChildLoop`) maxRounds 32→64 with the same anti-summary wording. Model in-between text is persisted before its tool turns; `toolLabel` renders call summaries.
- SDK (`pkg/sdk/sdk.go`): `GetSession` (includes `running`), `SessionState` (resync payload), `ExportTranscript`/`TranscriptTurn` (full persisted timeline).
- Tests added: `variant_matrix_test`, `continue_tool_test`, `resync_test` (TUI); `effort_matrix_test`, `resync_test`, `sessions_list_test` (server).
- 2026-10-31 deltas: TUI default effort `""`→`xhigh` (Go `New()` + Rust `App`, web parity; `/effort auto` still resets to provider default; matrix tests updated). Empty-final guard: a turn ending with blank text gets one tools-stripped round asking for done-vs-remaining, else a canned resume pointer (`TestEmptyFinalGuarded` Go + `guard_tests` Rust) — fixes 0-char assistant turns seen after long non-converging runs. Pure-empty passthrough: silence with zero tool calls returns as-is with no guard round trip (`TestEmptyFinalNoWorkPassesThrough` Go, `empty_final_without_work_passes_through` Rust, 1 backend hit asserted). Gateway note: opencode_go `/models` returns id+name only (28 models incl. `muse-spark-1.3-contributor`, verified live) — no `supported_efforts`/`context_length` advertised, so `ClampEffort` stays future-use; `NormalizeEffort` validation is the live enforcement.
